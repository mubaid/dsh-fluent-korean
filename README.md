# fluent-korean for DeepSeek Harness

한국어 | [English](README.en.md)

DeepSeek Harness가 한국인이 받아들일 한국어를 쓰게 하세요.

코딩 에이전트는 짧게 말하도록 맞춰져 있습니다. 조사를 떨어뜨리고, 어미를
뱉지 않고, 문장을 전보처럼 명사만 늘어놓고, 평이한 말 대신 비유적인 말을
고릅니다. 그래서 결과물은 읽힙니다. 다만 무엇이 빠졌는지 이미 아는 사람에게만요.

이 플러그인은 모델의 지시문에 글쓰기 규칙 한 벌을 더해 줍니다. 덕분에 문장이
온전해지고, 말하려던 것을 그대로 하는 말을 고르게 됩니다. 이 규칙은
[`snflkd/fluent-korean`](https://github.com/snflkd/fluent-korean)에 있습니다.
국어국문학 전공자가 이걸 읽는 게 지겹다고 썼습니다.

---

## 왜 필요할 수 있나

에이전트에게 한국어로 지시하면, 답을 두 번 읽게 됩니다. 한 번은 무슨 뜻인지
읽는 거고, 또 한 번은 '설마 이 뜻이었나'를 확인하는 겁니다. 결과물에 한국어가
섞이면 언제나 같은 세금이 붙습니다. 에이전트가 써준 코드 주석과 커밋 메시지도
마찬가지입니다.

이를 더 심하게 만드는 건 두 가지입니다. 하나는 컨텍스트 길이. 에이전트는
토큰을 아끼려고 짧게 대답하라고 맞춰져 있고, 한국어에서 짧다는 건 문장을
문장답게 만들어 주는 어미를 떨치는 것과 같습니다. 다른 하나는 누적입니다.
에이전트가 서브에이전트에게 일을 넘기고, 그 답이 다시 당신에게 돌아올 때마다
한 번 지날 때마다 조금씩 더 잃습니다.

같은 모델에, 같은 질문을 하고, 프로젝트를 한국어 세 문장으로 소개해 달라고
했습니다.

**규칙 없이:**

> 이 저장소는 DeepSeek Harness라는 AI 에이전트 하네스를 담고 있으며... 일회성(oneshot) 프로파일...

'one-shot'을 평이한 한국어 말로 바로 떠올리지 못하고, `일회성(oneshot)`이라는
풀이를 붙였습니다. 문장 자체는 문제가 아닙니다. 그저 한국인이 쓴다면 나올
문체보다 조금 밋밋합니다.

**규칙과 함께:**

> ...일회성 실행 프로파일... 이벤트를 줄 단위 JSON 이벤트 스트림으로 투영하고...

어미가 온전합니다. 한자어 기술 용어를 한국인 엔지니어가 쓰는 방식 그대로
씁니다. 특별한 게 아닙니다. 그저 기대했던 문체입니다.

다만 이 비교의 한계는 분명히 말씀드리는 편이 맞습니다. 우리가 시험한 모델은
원래 한국어 실력이 괜찮았습니다. 그래서 이건 깨진 출력을 구해 주는 일이 아니라
문체를 한 칸 옮겨 주는 일입니다. 약한 모델에서는 효과를 더 크게 느끼실 겁니다.
강한 모델에서는 기적까지는 기대하지 마세요.

## 왜 Harness 플러그인인가

원본은 Claude Code 플러그인입니다. Claude Code 사용자라면 명령 한 줄로 설치가
됐고, 나머지 분들에게는 저장소에서 규칙을 꺼내 아무 데나 붙여 넣으라고 했습니다.
갱신하기 전까지는 그럴듯하게 동작하는데, 갱신하고 나면 조용히 낡아버립니다.

여기서는 같은 규칙을 DeepSeek Harness용으로 묶었습니다. 한 번 설치하고
Settings에서 스타일을 고르면 모든 세션에 적용됩니다.

규칙 자체는 그대로입니다. 한국어 한 글자도 손대지 않았습니다. 원저자가 이
규칙을 모델이 지시문으로 읽도록 쓴 글이고, 모든 줄에는 뜻이 그대로 보이도록
예시가 붙어 있습니다. 거기를 고치면 규칙이 동작하는 이유까지 함께 지워집니다.
이 플러그인은 패키징이지, 집필이 아닙니다.

Harness 에이전트가 아닌 모델에서 이 규칙을 쓰고 싶다면, 원본 저장소에 여전히
평범한 텍스트로 남아 있습니다.

## 두 가지 스타일

Settings에서 하나를 고르세요. 차이는 크지 않습니다.

| 스타일 | 언제 쓰나 |
| --- | --- |
| **Fluent Korean** | 에이전트가 코드와 한국어를 함께 씁니다. 이 쪽은 서브에이전트를 부르기 전에 자신의 한국어도 한 번 점검합니다. |
| **Fluent Korean (non-coding)** | 에이전트가 코드를 고치는 일이 없어서, 서브에이전트 관련 문장은 쓸모가 없습니다. |

> **Claude Code 버전과 다른 점, 정직하게 말씀드립니다.** Claude Code에서는
> "non-coding" 스타일을 고르면 내장된 코딩 지침이 제거됩니다. Harness의 최상위
> 레벨에서는 그럴 수 없습니다. 시스템 프롬프트 전체를 교체할 수 있는 그
> 구성 요소가 단일 에이전트 스코프 안에서만 동작하기 때문입니다. 그래서 여기서는
> 두 스타일 모두 한국어 지침을 더할 뿐, Harness의 코딩 지침은 어느 쪽도
> 제거하지 않습니다. 두 번째 스타일이 코딩 규칙을 꺼 줄 거라 생각하셨다면,
> 꺼 주지 않습니다.

## 설치

에이전트에게 물어보세요. 한 문장이면 되고, 대부분 제대로 해냅니다.

```
https://github.com/mubaid/dsh-fluent-korean 링크 README 읽고, 설치 안내 단락 읽고 어떻게 설치해서 사용할지 설명해줘
```

직접 하셔도 됩니다.

```
dsh plugin add mubaid/dsh-fluent-korean
```

그다음 **Settings → Plugins → Fluent Korean**을 열고 스타일을 고르세요. 파일을
직접 고칠 일은 없습니다. 변경 사항은 다음 세션이 아니라 다음 메시지부터
반영됩니다.

## 더 보고 싶은 경우

원저자가 기본 규칙이 아직 다루지 못하는 상황을 위한 추가 문항도 공개했습니다.
필요한 것은 에이전트에게 규칙 맨 뒤에 붙여 달라고 하시면 됩니다. 위치를
에이전트가 알고 있습니다.

**코딩을 처음 접한다면, 에이전트가 쉽게 풀어서 설명해 주길 바란다면:**

```
- 코딩에 관해서는 초보 개발자가 이해할 수 있도록 서술하고, 현장감이 과한 구어체 표현은 더욱 자제합니다. (박아넣다, 치우다, 얹다 등)
```

**정중하게 말해 달라면:**

```
- 사용자를 '사용자님'이라고 호칭하고, 선어말어미와 어말어미, 조사, 공손어휘를 통해 사용자께 높임말을 사용합니다. 사용자에게 반말이나 비존대로 발화하지 않습니다. [네가 한 말대로 내가 진행할까? → '사용자님'께서 하신 말씀대로 제가 진행하면 될까요?]
```

**답만 한국어로 말고, 생각 자체도 한국어로 하게 하려면:**

```
- 항상, 한국어로 사고하고, 한국어로 보고하고, 한국어로 출력합니다.
```

**자기만의 규칙이 있는 글쓰기를 하신다면 — 소설, 대본, 출제:**

```
- 구체적인 지침이 따로 존재하는 산출물 유형에는 이 지침을 적용하지 않습니다. 적용 여부가 애매하다면 사용자에게 확인합니다.
```

전체 모음과 각 문항에 대한 더 자세한 설명은 원본 저장소에 있습니다.

## 알아두면 좋은 것

- **토큰을 조금 더 씁니다.** 지워 놓았던 문장 성분과 어미를 되돌려 놓기
  때문입니다. 메시지 길이와 컨텍스트 사용량이 조금 늘어납니다.
- **강제가 아니라 권고입니다.** 작업이 길어질수록, 다른 지시들이 주의를
  끌어갈수록 규칙은 조금씩 흐려집니다. 주요 결과물에서 문체가 무너지는 게
  보이면, 결과를 넘기기 전에 스스로 규칙에 맞춰 점검하라고 에이전트에게
  말해 주세요.
- **한국어 출력에만 적용됩니다.** 번역하라는 지시가 아닙니다. 작업이 영어를
  요구하면 영어를 받습니다.
